Вопрос 1
npm — это магазин готовых кусочков кода. Когда ты ставишь чужую штуку (npm install axios), она называется пакетом. А npm — это и реестр (огромная база всех пакетов), и программа, которая их скачивает и ставит.
package.json - это паспорт проекта. Один файл, который лежит в корне и рассказывает npm, что это за проект. В нём:
  name, version - имя и версия пакета.
  dependencies - от каких чужих пакетов зависит проект (что npm должен скачать).
  main: "index.js" - главный вход. Когда кто-то другой подключит твой пакет через require('твой-пакет'), он получит именно этот файл.
  module: "index.mjs" - вариант главного входа для новых модулей ES (об этом ниже). Если пакет поддерживает и старый, и новый стиль, main для старых, module для современных инструментов.
  type: "module" - говорит Node.js: в этом проекте я хочу новый синтаксис импорта import/export, а не старый require. Если поля нет, считается старый стиль (CommonJS)
  scripts - удобные ярлыки для команд. Внутри пишешь названия команд, и npm их запускает за тебя:
  Запускаешь так: npm run test, npm start (для start и test слово run можно опускать).

Вопрос 2
Эти три метода идут по элементам массива слева направо, платят за каждый. В каждом ты даёшь им функцию-колбэк (функцию, которую ты передал, чтобы их вызвали для каждого элемента)
map - преобразуй каждый элемент.
Колбэк превращает элемент во что-то другое, ответ для каждого записывается.
Инвариант: все три метода отвечают одинаково, и это и есть твой ответ на урок. Дальше по-человечески:

filter - оставь только подходящие
Колбэк - это предикат: функция, которая на каждый элемент отвечает да/нет (true/false).
Инвариант: длина нового массива ≤ длины исходного. Иногда может быть 0 (если ни один не подошёл), иногда равна исходной (если подошли все), но больше исходной быть не может - мы же только забираем, ничего не добавляем.

find - найди первый подходящий
Колбэк тоже предикат 
Инвариант самый заметный: find возвращает один элемент (самый первый, где предикат дал true) или undefined, если таких нет. Получается, "длина результата" всегда либо 1, либо 0 = не массив вообще, а один элемент.
Ранний выход (Early Exit) в find: он не обязан проходить весь массив. Как только нашёл первый подходящий — сразу останавливается и возвращает его. Если у тебя массив из миллиона элементов и нужный стоит первым, он проверит только первый и всё. map и filter так не умеют — они обязаны пробежать каждый элемент до конца (надо же собрать ответы/проверить все)
